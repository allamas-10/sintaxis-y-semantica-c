Análisis comparativo entre de strings entre C# y C.
El lenguaje C y C# son de distintas épocas. C# viene de herencia de C y. por lo tanto, hereda su sintaxis básica, pero a su vez hay que saber que es más moderno y de más alto nivel orientado a objetos. Específicamente vamos a analizar las diferencias y similitudes en los strings.
En el lenguaje C, el string no es un tipo de dato nativo, sino que es un array de caracteres (tipo char) y que finaliza en el carácter nulo '/0'. Por ende, las operaciones sobre las cadenas no las trae nativamente el lenguaje, sino que las trae su biblioteca estándar <string.h> que trae funciones como strcpy (que copia una cadena de caracteres) o strlen (mide el largo de la cadena). Por el otro lado, tenemos a C# si existe el tipo de dato "string" siendo una palabra nativa del lenguaje. Pero hay que entender que esta palabra es un alias de una clase "System.String" que proviene de la biblioteca de clases base. Esto quiere decir que C# integra a nivel sintáctico el string pero delega la lógica compleja a una clase de su biblioteca.
El alfabeto (el cómo se traduce los números de bytes en la memoria en caracteres legibles por pantalla) de C, como predominaba en la época de su creación el ASCII que usa un byte por carácter, se decide optar por este. Esto trae como consecuencia estar limitado a las letras del inglés y símbolos básicos. El soporte nativo de Unicode y UTF-8, que son estándares que soportan todos los idiomas, es muy limitado, para operarlos el programador debe manipular los bytes manualmente o utilizar bibliotecas de terceros y usar tipos de datos especiales como wchar_t (caracteres anchos). En contraparte, como C# nació en la época moderna, donde estaba más predominante el Unicode (en especial el UTF-16) lo utiliza como forma nativa para todos sus strings. Cada carácter representa 2 bytes permitiendo representar alfabetos internacionales por defecto. También contiene soporte nativo proveniente de la clase System.Text.Encoding para convertir textos hacia y desde UTF-8 o ASCII.
La alocación de la memoria (proceso el cual el sistema operativo reserva un espacio físico en la memoria principal para que el programa guarde sus datos mientras se ejecuta) en C delega la responsabilidad al programador. Por lo tanto debe calcular cuántos caracteres tendrá la cadena sumándole el carácter nulo y pedir memoria al sistema de forma manual (para esto se utiliza la función malloc). Si el programador se olvida de liberar esa memoria a través de un free(), se produce una fuga de memoria (memory leak). Si intenta escribir más caracteres de los reservados, ocurre un desbordamiento. Las cadenas también son mutables, esto quiere decir que podes cambiar un carácter individual directamente de la dirección de la memoria. Por otro lado, en C#, la memoria se asigna automáticamente de manera dinámica en el Managed Heap (un área de memoria controlada). Entonces el programador solo debe escribir string texto = "Hola mundo". Cuando el string ya no se usa, un componente Gargage Collector (o Recolector de basura) detecta qué esta en desuso y libera la memoria automáticamente, así poder evitar las fugas de memoria. Además los strings son inmutables, una vez que se crea el string no se puede modificar, si se modifica un carácter se reserva memoria nueva y se crea un objeto string completamente distinto.
En C los strings no se tratan con la misma facilidad que a un entero (por ejemplo comparar, asignarle un valor con =, devolver de una función de manera natural, etc) esto quiere decir que no es First-Class Citizen. Para asignarle un arreglo a otro se tienen que usar funciones de biblioteca (strcpy). Si se compara "Hola" == "Hola", se utiliza las direcciones de memoria por lo tanto va a dar un resultado erróneo, para eso se utiliza el strcmp. En contraposición tenemos a C#, donde el string si es un First-Class Citizen, por ejemplo el lenguaje sí permite usar operadores como el '+' para unir cadenas y el '==' para comparar, lo que abstrae la complejidad del tratamiento de strings.
El pasaje de un string como parámetro de una función en C se hace a través de la dirección de memoria del primer carácter. Esto tiene como consecuencia que el receptor tiene acceso a la memoria original y por lo tanto puede alterar el contenido. Para retornarlo hay una complejidad, ya que si se retorna la memoria de un string creado temporalmente dentro de la función (variable local), esa memoria se destruye al salir de la función, generando un error crítico. Solo puede retornar el puntero al inicio de la cadena y explícitamente la tiene que crear con un malloc para guardarlo en el heap. En C# se pasa una referencia al objeto en memoria. Gracias a la propiedad de la inmutabilidad, la función receptora no puede alterar la cadena, cualquier cambio que se haga se realiza sobre el string nuevo local. La función retorna a su vez la referencia al objeto string. El garbage collector se encarga de que el texto no sea eliminado de la memoria mientras la variable que lo recibe lo siga necesitando.
